## 一句话定位

一个汇集失败创业项目的微信小程序——为每一次失败立碑，让教训可以被检索、被复用。

## 要解决的问题

创业复盘信息目前散落在朋友圈、知乎回答、关停的公众号里。三个后果：

1. **搜不到** —— 内容孤立，没有结构，无法按行业、时间、金额检索
2. **传不下** —— 平台一关停，内容随之消失
3. **没人看** —— 长文劝退，缺少入口和浏览路径

结果是：每次创业失败，付出的代价无法沉淀为下一次的判断依据。

## 核心洞察

失败案例的价值不在于「 sympathy」，而在于**因果链完整**：

```
项目是谁 → 做了什么 → 花了多少钱 → 哪一步就注定会死 → 最后怎么死的
        → 留下什么教训 → 今天还有没有机会
```

其中「哪一步就注定会死」与「今天还有没有机会」是差异化重点。
多数失败案例集只记录到「怎么死的」，
本项目要求发布者必须回答「留下什么」和「今天还有没有机会」。

### 因果链必须拆成两层（需求修订）

这条是**竞品调研后追加的需求**，不在最初的构想里。

CB Insights 2024 年 431 家样本的统计显示：
「资金耗尽」出现在 70% 的案例中，但它**几乎总是最后死因，不是根本问题**；
根因首位是产品市场匹配失败（43%）。

如果只留一个自由文本的原因字段，70% 的记录会写成「钱烧完了」——
数据看起来很充实，但检索价值接近于零。
**一份全是死因的失败数据库，检索价值为零。**

所以「死于什么原因」被拆成两个**受控词表**字段：

| 字段 | 问的问题 | 词表 | 必填 |
|:--|:--|:--|:--:|
| `causeRoot` 根因 | 哪一步就注定会死 | 13 项，源自 CB Insights 失败原因分类 | ✅ |
| `causeSymptom` 死因 | 最后怎么死的 | 12 项 | ✅ |

用受控词表而不是自由文本，是因为**用户已经认得这些词**，
学习成本接近零，而聚合能力是全部价值所在。

词表与依据见[竞品分析](product/竞品分析.md)第三节。
落地范围：发布／编辑表单、详情页、搜索筛选、数据看板、演示数据。
健康度指标「死因单一化率 ≤ 30%」用于监控这套设计是否失效
（见[指标体系](product/指标体系.md)第三节）。

**这条需求本身是一个假设，不是结论。** 若投稿转化率低于 2%，
说明结构化取舍已被证伪，见[用户旅程](product/用户旅程.md) H5。

## 功能规格

### 浏览侧

| 功能 | 要求 |
|:--|:--|
| 项目列表 | 卡片流，支持 全部／热门／最多致敬 三种排序（`createdAt` / `views` / `likes` 降序） |
| 交互 | 下拉刷新 + 上拉加载分页 |
| 详情 | 完整字段展示、**根因与死因两层标签**、点赞致敬、收藏、评论、浏览量统计、分享转发 |
| 搜索 | 关键词检索（标题）+ 行业筛选 + **根因筛选** |
| 数据看板 | 项目总数、总投入金额、总浏览量、总致敬数、行业／根因／死因分布 |

### 贡献侧

| 功能 | 要求 |
|:--|:--|
| 发布 | 完整表单，10 个必填字段，含字段校验、照片上传、标签管理 |
| 编辑 | 修改已发布项目内容与照片（走同一套服务端白名单） |
| 删除 | 仅限本人，同时清理关联的点赞／评论／收藏 |
| 演示数据 | `initTestData` 灌入 6 个示例项目 + 6 位导师，需 `ALLOW_SEED_DATA` 闸门 |

### 账号侧

| 功能 | 要求 |
|:--|:--|
| 登录 | **静默登录**，无授权弹窗，`wx.cloud` 隐式换取 openid |
| 资料 | 昵称、头像、简介 |
| 我的 | 我的项目、我的收藏、消息通知、数据看板 |

### 商业化侧（可选）

| 功能 | 要求 |
|:--|:--|
| VIP | 会员订阅页 + 权益说明（**支付未接入，只建待支付订单**） |
| 咨询 | 付费咨询下单（**定价由服务端从 `advisors` 读取**） |
| 订单 | `createOrder` / `createConsultation` |

详见 [商业化](商业化.md)。

### 数据与指标侧

| 功能 | 要求 |
|:--|:--|
| 埋点 | 19 个事件，走独立云函数通道，`events` 集合客户端不可写 |
| 统计 | 聚合必须在云函数（小程序端 SDK 单次查询上限 20 条） |
| 行为计数 | 浏览与点赞必须在服务端（客户端改不了别人的项目） |

详见 [埋点方案](product/埋点方案.md) 与[数据模型](数据模型.md)。

## 硬性约束

| 约束 | 说明 |
|:--|:--|
| **严禁蓝紫色** | 产品级视觉约束，任何界面不得出现。`check.ps1` 自动扫 3 位 hex、`rgb()`、`rgba()`，色相 200°–320° 一律报错 |
| 复古怀旧风 | 棕色 / 米色 / 灰色系，衬线字体 |
| 逻辑闭环 | 所有页面与功能完整开发，不留占位页、不留死链 |
| 云开发 | 必须使用云函数 + 云数据库，不引入自建后端 |
| 静默登录 | 不得弹出授权弹窗 |
| **文档不得声称代码里没有的东西** | 数量、事件名、集合、字段一律以代码为准，由 `check.ps1` 双向校验 |
| **数值缺失显示 `—`** | 不显示 `0` 或默认值（无评分导师默认 5.0 属于伪造口碑） |

## 信息架构

```
底部 TabBar
├── 墓志铭（首页）    项目流
├── 搜索              检索 + 筛选
├── 立碑（发布）      贡献入口
└── 我的              账号中心
     ├── 我的项目
     ├── 我的收藏
     ├── 编辑资料
     ├── 数据看板
     ├── 消息通知
     ├── VIP
     └── 创业咨询
```

二级页面：`项目详情`、`编辑项目`。

## 技术约束

| 层 | 选型 |
|:--|:--|
| 前端 | 微信小程序原生，无第三方 UI 库 |
| 后端 | 腾讯云开发（云函数 + 云数据库 + 云存储） |
| 运行时 | 基础库 ≥ 2.2.3，Node.js，`wx-server-sdk ~2.6.3` |

## 非目标

以下明确不在当前版本范围内：

- 用户间的私信 / IM
- 视频与音频内容
- 多语言 / 国际化
- 原生 App 或 H5 版本
- **模板投稿、草稿箱** —— 结构化字段已抬高门槛，再加编辑态会堵死供给侧
- **广告变现** —— 与北极星指标冲突，且早期无流量，详见[商业化](商业化.md)
- **注册流程** —— 静默登录，没有注册动作
- **PDF 报告下载** —— 当前没有这份内容，写进 VIP 权益属于欺诈
