## 一、变现体系

三条线，按**毛利与合规难度**排序，不按上线顺序排序。

### 1. 创业咨询（理论上毛利最高，但合规最重）

一对一咨询，按行业匹配导师。

| 项 | 值 |
|:--|:--|
| 定价 | `advisors.price`，¥79 – ¥159/次，由导师自己定 |
| 会员折扣 | 8 折，**在服务端算** |
| 分成 | 平台 30% / 导师 70%（待定，见第七节） |
| 交付形式 | 语音 / 文字 / 视频 |

**这是理论上最健康的一条线**：一次交付的收入远高于订阅，
且需求由供给端（内容库）自然带出来——用户先在墓志铭里看到
「教育行业死因 Top 1 是定价」，然后才会想找这个行业的人聊两句。
**咨询是这个产品变现逻辑最顺的出口**，因为需求和供给在同一个产品内闭环。

但它也是唯一一条**必须先解决资质**才能上线的线（见第六节）。

### 2. VIP 会员订阅

| 套餐 | 价格 | 服务端键 |
|:--|:--|:--|
| 月度会员 | ¥19 / 30 天 | `plan: 'month'` |
| 年度会员 | ¥199 / 365 天 | `plan: 'year'` |

权益（**当前均未实现**，且支付未接入前一条都不能给）：

| 权益 | 状态 | 备注 |
|:--|:--|:--|
| 咨询 8 折 | ✅ 已实现 | 服务端 `createConsultation` 按 `users.isVip` 算 |
| 无广告纯净体验 | ❌ 无广告位 | 权益为空，见下方说明 |
| 下载行业分析报告 | ❌ 无此内容 | **不写进权益列表**——给了没有的东西是欺诈 |
| 专属 VIP 标识 | ❌ 未实现 | |
| 优先参与线下活动 | ❌ 无此活动 | 同上 |

> 早期阶段把**没有实现的权益写进营销页**是自欺。这一点与
> 「不追不存在的指标」是同一个原则：文档声称 A、代码是 B，
> 而这类不一致**不需要谁来揭穿，它自己会露出来**——
> 真实用户点进去发现没有，仅此而已。
> 本仓库吃过这个亏，见 [README §二](../README.md)。

### 3. 广告（**当前不采用**）

原方案有首页 Banner、详情页底部、搜索结果页三个广告位。
**现已从设计里移除。**

理由是三条，都不是客套话：

1. **与北极星指标直接冲突**。MVPR 要求消费侧体验干净，
   而详情页插广告会直接压低阅读深度。
2. **P0 用户不会看广告**。[用户旅程](product/用户旅程.md) 判定目标用户是
   「踩坑中的创业者」和「创业前的研究者」，不是泛围观者。
   卖给 P2 看的广告位，对 P0/P1 是纯噪音。
3. **早期没有流量，广告位收益≈0，但它是永久性的体验债**。

这一条属于 [README §四](../README.md#四取舍) 里的「不做什么」：
砍掉一条收入线，代价是短期收入，收益是产品定位不被稀释。

## 二、定价与依据

不写「为什么是这个价」的定价，等于没有决策。

| 定价 | 值 | 依据 | 敏感度 |
|:--|:--|:--|:--|
| 导师咨询 | ¥79 – ¥159 | 对标「在行」「知识星球」同类 1v1 咨询的 ¥100–300 区间，**取下沿** | 定价定在 ¥200+ 时，早期无人下单；定在 ¥49 以下会吸引非目标用户 |
| VIP 月付 | ¥19 | 参照国内知识付费工具的月度订阅锚点（¥15–30） | 低于 ¥15 吸引的是薅羊毛用户，高于 ¥30 需要「每月都有新内容」来支撑 |
| VIP 年付 | ¥199 | 年付/月付 = 8.7 折，比月付的 8 折会员咨询折扣更深，形成双层折扣 | 年付占比过高会掩盖「月度留存」这个真实健康度信号 |

**两个可以调的旋钮：**

- **8 折深浅**。当前 8 折让 VIP 的省钱额（¥79 的咨询省 ¥15）**小于**
  年付会员的差价（¥228）。这意味着**买年付比单次享受 8 折更划算**，
  会员权益与会员价格之间存在不一致。
  改法二选一：把咨询折扣提到 9 折（即年付更划算，
  引导长期绑定），或把年付降到 ¥168（让咨询 8 折成为主推理由）。
  **这个不一致是当前定价里唯一可以确认的逻辑漏洞，记在这里而不是假装它不存在。**

- **导师分成比例**。当前写 30/70，但**导师侧的真实成本没有被核算过**
  ——一次 45 分钟咨询，导师的时间成本、平台获客分摊、
  7% 支付通道费、退款与纠纷处理，六项都没进模型。
  30% 是不是够用，**现在无法回答**。

## 三、技术实现现状

### 3.1 三个集合的字段

完整定义见[数据模型 · 集合 9-11](数据模型.md)。

| 集合 | 用途 | 关键字段 |
|:--|:--|:--|
| `orders` | VIP 订单 | `orderNo` `plan` `amount` `status` `vipDurationDays` `userId` |
| `advisors` | 导师（仅控制台维护） | `name` `title` `price` `rating` `isVip` `status` `sort` |
| `consultations` | 咨询记录 | `advisorId` `advisorName` `originalPrice` `price` `discountApplied` `status` |

### 3.2 两个页面

| 页面 | 状态 |
|:--|:--|
| `pages/consulting/consulting` | ✅ 完整：导师列表、评分、咨询记录列表、下单 |
| `pages/vip/vip` | ✅ 完整：套餐对比、下单 |
| `pages/profile/profile` | ✅ 会员入口（**不在首页**） |

商业化入口**刻意不做在首页**。这是 [README §四](../README.md#四取舍) 的第三条判断：
早期没有转化数据，提前铺商业化会污染产品定位和北极星指标。
一个首屏就在推 ¥199 的产品，MVP 的定义就变了。

### 3.3 两个云函数

| 云函数 | 现状 |
|:--|:--|
| `createOrder` | 建 `pending` 订单，**不发放权益** |
| `createConsultation` | 建 `pending_payment` 记录，不建 `orders`，**不发放权益** |

### 3.4 三处安全修复（这一版的主要工作）

原来的商业化代码有三条完整的提权路径，现已全部关闭：

| 原缺陷 | 攻击方式 | 现在 |
|:--|:--|:--|
| **订单一建即发权益** | 点一下「立即开通」→ `status: 'paid'` + `isVip: true` | `status` 恒为 `pending`；权益只能由支付回调写 |
| **价格全信客户端** | `callFunction({name:'createConsultation', data:{advisorId, advisorName, price: 0}})` | 姓名与定价一律从 `advisors` 读；8 折在服务端算 |
| **客户端可自行提权** | `db.collection('users').where({_openid: 我}).update({isVip: true})` | 资料修改走 `updateProfile`，只接受 3 字段白名单；`isVip` 只由支付回调写 |

第二条尤其值得说明：原代码是
`const { advisorId, advisorName, price } = event`——
三项全部来自客户端。定价是商业模式的底线，不能由购买方决定。

另外，订单号改用 `crypto.randomBytes` 而非 `Math.random`。
订单号是可追溯的财务凭证，`Math.random` 不是密码学安全的随机源。

## 四、接入支付需要补的部分

支付**尚未接入**。补齐它需要 5 件事，顺序不能换：

| # | 事项 | 说明 |
|:--|:--|:--|
| 1 | `cloud.cloudPay.unifiedOrder` 拿 `prepay_id` | 服务端下单 |
| 2 | 客户端 `wx.requestPayment` | 发起支付 |
| 3 | 新增 `payNotify` 云函数接收回调 | 校验 `out_trade_no` 与金额一致 |
| 4 | 回调幂等 | 同一 `out_trade_no` 只发放一次 |
| 5 | 权益发放逻辑抽成独立函数 | **不要留在 `createOrder` 里**，由 `payNotify` 复用 |

第 3 步是唯一的安全边界。**订单状态只能由支付回调改**，
`createOrder` 自己永远不写 `paid`。这条边界一旦模糊，
「点一下按钮就成会员」就会重新出现。

配套还需要：退款流程、订单状态机校验
（现在任何状态都可写，接入支付后必须补）、对账。

> ⚠️ 微信小程序支付需要 ICP 备案，且**咨询服务类目可能需要额外资质**。
> 这是三条收入线里最可能直接否掉「咨询」这条线的原因，
> 不是排期问题。详见[第六节](#六合规提示)。

## 五、为什么本文没有盈利预测

原稿有这一节：

```markdown
### 保守预测（首年）
- VIP会员：2000人 × ¥199 = ¥40万
...
- **合计：¥50万**
```

**已删除。** 原因不是不好听，是这些数字不可辩护。

| 问题 | 说明 |
|:--|:--|
| **2000 个付费用户从哪来** | 全文没有一个字解释。用户量假设是预测的**全部**依据，而它是凭空写的 |
| **留存率假设缺失** | 2000 人里如果次月留存 5%，一年后只剩个位数。算式里没有留存这一步 |
| **漏斗各层都没有依据** | 曝光 → 打开 → 阅读 → 咨询页 → 下单，每一层的转化率都是猜的 |
| **咨询 500 单** | 6 个演示导师、¥99 单价。500 单意味着人均 83 单，而咨询是非标服务，产能从哪来 |
| **广告 ¥5 万** | 这一条已随广告方案一起删除（见第一节） |
| **零成本假设** | 云开发、云存储、导师分成、支付通道费、退款，全部没进模型 |

**一个编造的预测，比一个承认算不出来的预测危险得多。**
不需要谁来追问「2000 人怎么来的」——只要有人顺着算式往下走一步，
编的数字就撑不住了。而且比没有数字更伤：
**它会让人怀疑你其它所有数字的来源。**

这也是本仓库删掉那两行预测的唯一理由，与好不好看无关。

### 替换成什么

不是删掉了事，而是换成**可检验的推导链**：

| 需要的输入 | 现状 | 何时可得 |
|:--|:--|:--|
| 曝光 → 进小程序 | 无数据 | 上线后 |
| 进入 → 读一条 | 无数据 | 上线后（对应 `app_launch` / `project_view`） |
| 读 → 进咨询页 | 无数据 | 上线后（对应 `project_favorite` / `consult_page_view`） |
| 咨询页 → 下单 | 无数据 | 上线后（对应 `order_submit`） |
| 导师产能 | **未核算** | 现在就能算，且不依赖上线 |
| 成本结构 | **未核算** | 现在就能算，且不依赖上线 |

**最后两项不依赖任何用户数据，现在就能做，
但原文档没做。** 这是「预测」和「准备」的区别：
与其预测收入，不如先把不依赖收入的变量算清楚。

对应的做法是：上线后用 [指标体系](product/指标体系.md) 里的 12 个指标
逐步替换上表的「无数据」，**每替换一个，预测的置信度就上升一档**，
并且在文档里标注当前用到第几档。这样得到的数字可以被追问，也可以被修正。

## 六、合规提示

### 硬门槛（缺一即无法上线）

| 项 | 服务于 | 说明 |
|:--|:--|:--|
| **ICP 备案** | 微信支付 | 缺备案无法开通支付 |
| **类目资质** | 咨询 | 「咨询服务」类目可能要求经营主体、咨询师资质。**这可能直接否掉「咨询」这条线** |
| **用户隐私保护指引** | 全部 | 微信审核必备，涉及头像等信息收集 |
| **用户协议 + 社区规范** | 全部 | 涉及用户发布内容，必须有投诉与下架机制 |

### 软风险

| 风险 | 说明 | 缓解 |
|:--|:--|:--|
| **内容合规** | 用户会写具体公司名，可能构成诽谤 | 举报入口 + 人工审核 + 免责声明。**当前均未实现**，见[发布检查清单](发布检查清单.md) |
| **免责声明不足** | 项目内容由用户自行发布，平台不保证真实性 | 必须在小程序内显著位置声明「不构成投资建议」 |
| **广告** | 需审核 | **已下线**，见第一节 |
| **隐私** | 埋点用哈希 `uid` 而非明文 openid，已是最小化设计 | 需在隐私指引中如实申报「收集使用情况」 |

### 一条容易忽略的

**免责声明不是法务形式，是产品责任划分。**
这个产品鼓励用户公开失败，其中涉及企业、竞品和个人的负面判断。
如果没有明确的「内容由发布者负责、平台不核实」声明，
出现名誉纠纷时平台的处境会很被动。这条要在**首次进入**就告知，
而不是塞在「关于」页面最深处。

## 七、运营假设

> 全部为**待验证假设**，不是策略承诺。

### 冷启动

| 假设 | 证伪信号 |
|:--|:--|
| 失败创业者愿意公开自己的失败经历 | 供给转化率（见指标体系）低于 2% |
| 前 20 个付费用户能靠邀请制获得 | 3 个月内付费用户为 0 |
| 愿意付费的人里有一部分是**同行**（创业服务方、投资人）而非创业者 | 咨询页的 `entry` 全部来自内部跳转，无外部来源 |

第三条假设最值得先验证。**如果付费的都是同行，
那么「咨询」这条线的定位就该从「给创业者提供经验」改成「给从业者提供线索」**——
这是完全不同的产品，也完全不同的定价。

### 内容

| 假设 | 证伪信号 |
|:--|:--|
| 定期发布行业失败分析能带来复访 | 复访率不高于无更新时 |
| 根因受控词表的学习成本可接受 | 死因单一化率 > 30%（见指标体系健康度表） |

### 增长

| 假设 | 状态 |
|:--|:--|
| 邀请制解锁高级功能 | **未做**。没有证据表明它有效，且会增加分享噪音 |
| 分销返利 | **未做**。过早，且与「严肃的失败复盘」调性冲突 |
| 企业客户定制 | **未做**。连 B 端付费意愿都没验证过，跳过 B 端是不理智的 |

三条增长手段全部标记「未做」。**不是因为它们不好，
而是因为每一个都建立在一个尚未成立的前提上。**
早期堆增长手段是拿战术掩盖战略问题。
